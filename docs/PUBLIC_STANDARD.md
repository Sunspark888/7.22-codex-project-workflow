# PMR · 公开网站发布与长期维护准则 V1.0

状态：`PUBLIC_SITE_STANDARD / LOCKED_2026-10-13`。

## 双轨架构

- **私人 PMR（正式）**：Drive 唯一入口、L1–L4 语义与原始来源、CrownRoute 研究图鉴 V5.1 工作副本、原版本备份、可追溯决策。科研数据与历史决定由私有来源管理。
- **公开网站（展示）**：PMR 产品说明、工作流、脱敏演示、标准原则与 GitHub 公开入口。公开演示的记录、表格和数值全部为合成、明确标注，不是科研证据。
- 公开版永远**不读取或自动镜像**私人 L1–L4、完整聊天、未发表研究、私有实验数值、私人 Drive 链接、部署凭据。

## 不可退化的用户已认可要求

1. 人类阅读的研究历程围绕论文的研究问题、方法与实验，而非私人状态或任务流水账；原文不随排版变更而改写。
2. 实验按科研问题分组；五方法独立、E1 与当前主结果有可比边界、七个 VCA 有明细、Random-B/All-B 同屏；数据、图、来源需可追溯。
3. “待议事项”必须为一级可见入口，并明确已处理、仍待议两种状态，不重开已关闭历史。
4. 页面使用固定渲染器、固定样式和数据结构；维护者可换，布局不会因模型降档漂移。已满意的实验页不得借其他修改随意重做。
5. 每次修改先写影响范围，再做局部改动；不可凭摘要创造研究结论。保留 V3、V4、V5、V5.1 历史版本与修改说明。
6. 普通验证为范围检查＋1次桌面／手机交互检查；默认不要求哈希和反复全量审计。

## 公开站必须遵守

- `index.html`：讲清 PMR 的价值与真实开发状态，不夸大已经部署的跨 Agent 自运行能力。
- `demo/`：纯前端交互，页面显著注明“所有数字为虚构演示”；公开代码不包含私人来源、私有 Drive URL、完整私有 HTML。
- 默认不安装追踪脚本、不采集访客个人信息、不依赖后端服务。
- 手机和桌面可读，导航、演示面板、搜索/筛选、导出按钮真实可用；不是静态截图。
- 公开网站内容与私人项目事实解耦；若未来要展示真实科研图表，需独立确认权属及公开许可。

## 检索技术的试验边界

- 当前检索仍是只读选配试点。分清证据召回率（Recall@K）、整题找齐率（all-required-hit）与最终 GPT 回答质量；不可混称“记忆准确率”。
- 开发题与新题集不可直接混成绩；回归旧题集要说明污染风险。
- 优先改进“编号直达、表格/原话/待议类型分流、多实体证据找全、已知来源定向补查”。
- 预算不足或来源缺失时标记 PARTIAL，不编造结果；检索不得推断用户授权。

## 维护流水线

私有确认状态 → 选择需要发布的非敏感摘要 → 更新公开代码 → 静态扫描 → 手机/桌面交互 → 提交静态站 → 核验公网 URL。

推荐：模型作判断；程序执行固定渲染与 QA；用户批准修改范围时可以直接实施，不需要层层额外审批。
