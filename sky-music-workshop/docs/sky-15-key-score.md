# 光遇十五键琴谱 Skill

**把不同排法的琴谱，整理成一套熟悉的读谱习惯。**

音区对应琴键三排，同时音对齐，快慢按时间槽排布。输入原始琴谱截图，经过转录和复核，输出封面、高清单页、四页合成和完整总谱。默认保留作者长期使用的版式，也允许选择尺寸、配色和封面风格。

[进入完整 Skill 源码](../skills/sky-15-key-score/SKILL.md) · [外观配置](../skills/sky-15-key-score/references/customization.md) · [完整数据示例](../skills/sky-15-key-score/examples/demo/manifest.json)

## 能做什么

- 三排琴键位置固定，不因来源谱子的排法变化而移动。
- 同时按下的音共用时间位置，同排多音使用紧凑音块。
- 用时间间距和快速横线表达连续关系，支持跨小节、跨行和跨页。
- 可选择单页尺寸、浅色主题、独立封面尺寸及风格。
- 单一构建入口，强制来源比较和全谱时间检查，输出实际文件清单。

它处理已有数字琴谱，不是从音频自动扒谱，视频由同项目的独立视频 Skill 负责。原始截图和字体不随包分发。示例为专门编写的合成数据，不是一首真实歌曲。

## 安装与第一次运行

建议 Node.js 22 或 24；最低20。数字字体使用 DejaVu Sans，需 fontconfig。Linux已实测；其他系统需先配好相同字体和fc-match命令。

```bash
git clone https://github.com/Sunspark888/7.22-codex-project-workflow.git
cd 7.22-codex-project-workflow/sky-music-workshop/skills/sky-15-key-score
npm ci
# Ubuntu/Debian 若缺少字体：
# sudo apt-get install fonts-dejavu-core fontconfig
npm run demo
```

演示输出位于 `examples/demo/final`，包含4张图片和 `build-report.json`。其中默认演示封面是纯色占位，不冒充正式摄影封面。

供 Codex 使用时，将整个 `sky-15-key-score` 目录复制到 `~/.codex/skills/`（Windows可使用用户目录下的 `.codex/skills/`），安装依赖后启动新会话。其他能读取文件并运行 Node.js 的模型代理，也可直接读取 SKILL.md 执行；仅有聊天、没有文件及代码执行工具的模型不能直接生成这套成品。

推荐运行配置：已复核的结构化数据与标准配置可用较轻模型、Low档执行脚本；密集或模糊截图的首次转录，使用有视觉能力的模型并保留独立复读。不要把模型名称当作准确率保证。

## 用户怎样说

默认版：

> 使用 $sky-15-key-score 整理这些琴谱截图。保持默认版式，交付全部单页、四页合成、总谱和封面。

个性化版：

> 使用 $sky-15-key-score，琴谱1920×1080，浅绿色，封面1080×1440，清新的草地云海风格。音符与节奏规则保持不变。

用户不必自己写代码。执行者把选择存入清单的 `presentation`。缺省使用我们的默认方案，不为选风格反复打断。

## 默认与可选项

| 项目 | 默认 | 可选择 |
| --- | --- | --- |
| 单页 | 2160×1080，每页3条谱面行 | 1920×1080、3840×2160、1080×1920、自定义宽高 |
| 谱面色调 | 浅蓝粉 | 浅绿mint、米白paper，也可提供低干扰背景图 |
| 封面 | 2048×2048，摄影优先 | 清新、插画、极简、用户描述；独立横/竖/方尺寸 |
| 数字、点、线 | 固定基准规格 | 随整页等比适配，不单独变形 |
| 四拼 | 左上P1、左下P2、右上P3、右下P4 | 自动跟随单页尺寸 |

自定义宽720–4096、高540–4096像素。尺寸不为2:1时采用留边适配，完整保留横谱，当前不做竖版音符重排。分辨率变高不等于手机上相对字号自动变大。

```json
"presentation": {
  "preset": "fullhd",
  "palette": "mint",
  "cover": {
    "style": "fresh",
    "width": 1080,
    "height": 1440,
    "layout": "cinematic",
    "brief": "浅绿草地与云海，标题融入画面留白"
  }
}
```

`cover.style` 与 `brief` 指导底图选取或生成；脚本只负责确定性排字，不会凭这些词自行生成风景。正式photo/fresh/illustration/custom封面须提供cover_art；minimal可使用纯色。中文标题需合法字体文件及真实字族名。

## 实际制作

1. 保留原图与来源顺序。
2. 按原图转录事件，再独立复读一次，保存来源账本。
3. 处理差异并记录；读不清的地方具体指出，不补造音符。
4. 准备封面底图和字体，运行：

```bash
node /path/to/sky-15-key-score/scripts/build.mjs /path/to/project/manifest.json
```

修谱复用原封面时加 `--reuse-cover`。输出中的 `build-report.json` 记录尺寸、步骤和文件。`rendered` 表示脚本生成完成，交付前仍要看图核对。

- `npm test`：24项通过，覆盖来源差异、错误音高、伴奏落点、断线、共享事件、时间间距、外观参数、实际导出尺寸与错误配置。
- 完整构建实际覆盖默认尺寸、1920×1080及1080×1920；封面独立1080×1440。
- GPT-6 Luna / Low，新会话无历史上下文，按包内说明独立完成默认和浅绿自选版，输出清单、尺寸及图像解码通过。
- 独立代理任务使用合成示例，验证了指令、配置与制作流程，不是弱模型对任意复杂截图的识谱准确率测试。未做跨全部模型、系统和档位的普遍保证。

## 为什么要“强规范”

可编码的排版与时间规则交给脚本；模型负责从来源读取事实、选择已经定义好的参数，并处理疑点。所有历史失败整理为[失败案例与固定处理](../skills/sky-15-key-score/references/failure-cases.md)。新版执行不需要翻旧聊天，也不依赖作者电脑上的绝对路径。
