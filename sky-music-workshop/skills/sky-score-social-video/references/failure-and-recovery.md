# 历史失败、证据与可恢复执行

## 已出现的失效模式

| 现象 | 原因与证据边界 | 固化措施 |
|---|---|---|
| P3 仍显示 P2 | 历史回复先说 concat 时长，后说 PNG 截断；没有原日志时不能把任一说法当已证实 | 图片完整解码；明确时间表达式；从最终编码文件抽取切换前后帧确认内容 |
| 视频或谱面看着糊 | 可能为预览降质、重复压缩、尺寸缩小或源文件本来低清；未比对前不归因 | 记录原始/输出参数，用同一时刻同一显示倍率抽帧比较；谱面直接用单页原图，音画最终合成尽量仅重编码一次 |
| 剪掉了正确反复/漏掉补录 | “重复”不等于“错弹”；源时间和输出时间混用 | 每段记录保留区间、替换原因和输出起点；剪完再重建锚点，保留原曲反复 |
| 游标跳错行、长音匀速扫过 | 套固定三行坐标、均分时间，忽略两行末页和停留 | 逐行真实 top/x 与演奏锚点；长音显式 hold；换行换页直接跳 |
| 默认变回整行框 | 主文默认与旧命令/旧模板冲突 | 唯一默认 cursor-project-example.json → render_cursor_video.py；旧行框仅用户明确要求 |
| 验收“通过”但最终成片错 | 原脚本抽的是编码前内存图；成功编码被当作同步正确 | 抽最终 MP4 帧；自动页面核对与人工游标/听辨结果分开记录 |
| 四平台封面裁字/风格分裂 | 按方形粗裁或把历史截图比例当永久规定 | 同主视觉重构，配置化比例、安全区与实看状态；不宣称未做的 App 检查 |
| 换进程找不到项目/旧路径失效 | 只存 scratch，或仅有成片没有结构化源数据 | 保存下述恢复包，读取稳定素材身份后重新定位本地路径 |

## 新进程最小恢复包

随交付保存 PROJECT.json（相对路径）、源文件稳定身份/名称、原视频和谱面版本、剪辑段与原因、音轨制作清单、锚点、已接受样片样式、known_issues、验收记录、输出文件索引。可复现成本高的音轨与锚点立即保存；中间帧可再生，不必全量保存。按当前环境的持久保存方式存项目，技能代码按 skill-creator 流程同步，不把本地临时路径当永久入口。

恢复顺序：读恢复包 → 定位真实素材 → 只检查缺失/变化项 → 从最后完成步骤接续。用户已经接受的样式和剪辑决定不用再问。缺失素材无法恢复时准确列出缺项，不声称已检查、已保存或已完成。

## 根因写入标准

每个新失败记录：现象、具体位置、已证实原因及证据、尚待排除的假设、代码/规则修复、一次有针对性的验证。未证实写“候选原因”；后续发现推翻时保留更正关系。不得为了表现确定性连续宣布多个互相替代的“真正原因”。

常规 QA 控制在 5–15 分钟；默认不做哈希、不设置层层确认。只做一次输入校验、最终解码、边界帧及接点试听，发现具体风险才补查。代码逻辑改变可跑短的合成素材回归，但不以全套重复渲染代替定位问题。
