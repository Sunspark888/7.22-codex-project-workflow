# 四平台发布封面规范 v1.0

## 1. 默认渠道

本项目的默认发布矩阵是：小红书、抖音、快手、视频号。公众号不默认发布，保留为用户的私人日记与长期写作空间。

用户只要说“发自媒体”“准备发布”或“给我发布版”，即使没有再次说“做封面”，也必须同时交付平台适配封面。

## 2. 封面家族

同一作品使用一个视觉母版，再针对平台比例重新构图，不能生成四张气质互不相干的图。

根据用户当前主页截图观察到的作品格展示，默认输出：

| 文件 | 默认尺寸 | 用途 |
|---|---:|---|
| `歌曲名_封面_主视觉_1x1.png` | 1080×1080 | 母版、归档与备用 |
| `歌曲名_封面_小红书_4x3.png` | 1440×1080 | 小红书当前主页横向作品格 |
| `歌曲名_封面_抖音_3x4.png` | 1080×1440 | 抖音当前主页竖向作品格 |
| `歌曲名_封面_快手_3x4.png` | 1080×1440 | 快手当前主页竖向作品格 |
| `歌曲名_封面_视频号_3x4.png` | 1080×1440 | 视频号当前主页竖向作品格 |

这些是当前账号界面观察到的展示比例，不视为永久不变的平台规则。正式发布前必须查看各 App 的封面选择预览；若平台界面或裁切框变化，按实际预览重新导出。

## 3. 跨比例安全区

- 歌名、核心主体和识别性最高的画面必须留在母版中央正方形安全区。
- 横向 4:3 与竖向 3:4 都优先使用“背景延展＋母版重构”，不能粗暴中心裁切。
- 重要文字距离最终边缘至少为短边的 6%；不要贴顶部状态栏、底部标题栏或右侧功能按钮区。
- 平台可能继续把 3:4 缩略图裁成更窄的预览，因此歌名和主体不放在最上/最下 12% 区域。
- 缩小到手机主页作品格后，歌名仍应一眼能读；解释性副标题允许消失，核心标题不允许消失。

## 4. 视觉与文案一致

- 封面延续歌曲封面和视频的色调、光线、字体气质与情绪，不另起一套模板。
- 封面短句与视频开头钩子表达同一个承诺，例如都强调“新手能直接跟”，但不必逐字重复。
- 信息层级最多三层：曲名；8–12 字价值短句；小号类别标识“光遇·十五键·跟弹谱”。
- 原主视觉已经清楚写有曲名时，不重复叠同一个标题。
- 不使用平台截图、播放器按钮、虚假播放量、账号水印或与歌曲无关的流量词。
- 风景主体优先保留。封面不是海报堆字比赛，第一眼应先有情绪，第二眼才读到用途。

## 5. 构建方式

优先使用 `scripts/render_platform_covers.py MANIFEST.json`：

1. 从 manifest 的 `social_cover.source` 或 `assets.cover` 读取已确认主视觉；
2. 完整解码并记录尺寸与来源路径；
3. 用同源模糊背景延展画布，将完整方形母版置于安全区；
4. 若指定 headline/subtitle，则使用确定性字体排版；非 ASCII 文案必须提供可显示中文的 `font_file`，不得输出方框字；
5. 原子写入全部 PNG，再完整解码并核对尺寸；
6. 输出 `covers.qc.json`，记录尺寸和内容安全框。

如果原主视觉无法通过重构适配（例如主体贴边、标题本身已被裁掉），重新生成或设计主视觉，再导出各平台版本；不得用拉伸变形解决。

## 6. 交付检查

- 四个平台都有明确命名的封面文件；
- 所有封面与视频、文案属于同一作品气质；
- 横版与竖版均没有拉伸、硬裁主体或重复标题；
- 在手机缩略图尺寸仍能识别曲名和主体；
- 记录发布页裁切预览是否实看；没有 App 访问时交付建议比例并注明未验证，不阻断本地交付；
- 直接展示/提供各 PNG，不默认打 ZIP。

可通过 `social_cover.variants` 覆盖默认比例，格式为 `{ "小红书_本次比例": [宽像素, 高像素], ... }`，四平台各保留一个输出。模板比例来自历史主页观察，不是当前平台强制规格。非方形源图必须等比保留，禁止强行拉成方形。
