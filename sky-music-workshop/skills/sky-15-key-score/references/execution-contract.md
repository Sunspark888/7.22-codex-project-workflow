# 无聊天上下文执行约定

## 输入与任务范围

用户说“做谱子”并提供截图：默认完整转录和标准图片交付。用户指出错误：定位来源页／行与输出页／行，检查同类错误并更新受影响输出。用户明确“先看方案”“只做样张”“本版先不改”：严格遵守范围。视频发布任务转交 sky-score-social-video；两个 Skill 共享确认过的琴谱，不能各自猜音符。

## 启动与恢复

1. 把当前加载的 Skill 根目录记为 SKILL_ROOT；读取本目录规范，调用本目录脚本。其他同名目录、旧聊天代码不属于本次有效实现。
2. 在项目目录保存原始素材索引、manifest、独立 source-review.json、输出以及简短 project-state.json。路径用项目内相对路径；输入／输出保留可得的持久文件 ID 和版本。不得只存临时绝对路径。
3. 状态至少包含 song、skill_revision、stage、inputs、manifest、source_review、outputs、known_issues、next_action。状态描述具体已做与待做，不能把计划写成完成。
4. 新进程先恢复此项目状态及原始素材，再从 next_action 继续；素材丢失时从已知持久引用取回。没有文件不等于没有交付过，不能凭旧聊天补造音符或宣称文件仍存在。
5. 附图在对话中可见、当地文件不可读时，可以说明可见内容；只有需要原始文件字节而确实取不回时才请用户补传。不要反复声称“没收到图片”。

## 唯一默认执行路径

依赖：Node.js、sharp、DejaVu Sans及fontconfig；封面中文字体需提供实际支持的字体文件。优先使用运行时已有依赖，缺失只报告或安装确实需要的一项，勿静默换字体。

从原图建立事件与来源 ID → 独立复读账本 → 解决差异 → 本目录 render_score.mjs → render_cover.mjs → compose_outputs.mjs → 轻量目视验收与保存。

命令均使用当前 SKILL_ROOT：

```bash
node "$SKILL_ROOT/scripts/build.mjs" project/manifest.json
```

修谱复用已确认封面时加 `--reuse-cover`。演示在 Skill 根目录 `npm run demo`。依赖安装 `npm install`，系统需要 DejaVu Sans和fontconfig（Linux可安装fonts-dejavu-core、fontconfig）。中文封面提供合法字体文件与字族名。包内不含用户截图、第三方曲谱或字体。

外观选择与全部默认值见 [customization.md](customization.md)。若用户未选择，不改变我们的默认风格。生成结果中 build-report.json 记录实际配置、尺寸和运行步骤；只把实际完成记入项目状态。失败后报告status=failed，不能交付混有旧页的目录冒充成功。

## 错误处理与交付

- 原图含糊：指出唯一具体位置，完成其他确定部分。软件异常：保留实际错误信息，先查输入／时间／图像解码；未验证的解释标为推测。
- 保存真实来源账本和生成清单，保证下一进程无需从最终 PNG 猜回事件。校验缺失不得用布尔字段补齐；不得关闭新版检查改用旧脚本。
- 修订替换同一持久文件身份，保留历史；先在临时位置生成并完整解码成功，再更新正式版本。
- 全套新作品按封面、全部单页、四页合成、总谱展示。局部纠错说明改动并展示修正页，提供更新后的合成和总谱；用户要求“所有图片”时逐张给全，不能只给一张样张。
- 只报告实际完成与验证范围。确定性代码保证版式和已编码约束；原图视觉歧义仍需依据，不能承诺任何输入都零错误。
